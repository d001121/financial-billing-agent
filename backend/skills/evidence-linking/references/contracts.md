# Evidence contract 2.0.0

The Agent judges material relationships. Version 2.0 removes the mandatory source_links identity-proof gate. Citations still resolve to actual source occurrences, and provided values still need original support. Extraction restores tool-generated ref_id values to exact quotes and offsets before this package runs. There is no fixed block checklist or second model read-back step.

LangChain Docs/API MCP checked 2026-10-21: structured output validates fields and types, and SkillsMiddleware binds ordinary Python functions to disclosed skills. They do not establish the exercise's original attachment occurrence identity or prove that a quote exists at a supplied anchor. This package supplies exact source lookup, quote read-back, explicit total-value support checks and a read-only projection of saved preview locations; it adds no Agent execution mechanism.

- API `deepagents.SkillsMiddleware`, source commit `9db018bf1b94c11f06ea4f33d69d133c34097e08`; include_tools requires >=0.7.22.

`link_evidence(payload)` returns `{valid,issues,charges,records,revision}`; `validate_evidence(payload)` additionally returns `total_evidence`. `charges` and `records` contain the same copied records for flat/nested consumers. Bare source text defaults to anchor `text`; aliases block_id/id are accepted. Anchors refer to immutable logical positions; physical page, bbox or Word render_version is retained only when supplied. Content hashes do not replace occurrence identities. The source host keeps original content; this package does not synthesize a filesystem, evidence store or citation retriever.

## International source support, 1.2.0

Docs MCP `/oss/python/langchain/structured-output` and API Reference MCP `langchain.agents.structured_output.ToolStrategy` were rechecked on 2026-10-21 for this change. The native schema and validation-error mechanism supplies typed proposals; it does not interpret global shipping-document numeric punctuation, resolve currency evidence or establish original field spans. This package adds only that deterministic domain responsibility. Installed LangChain/Deep Agents remains 1.4.6/0.7.29, with no new loader, Agent loop, Hook runtime or dependency. Existing `pycountry==26.2.16` supplies ISO codes/names; Python Decimal and Unicode decimal-character conversion supply exact numeric representations and digit normalization.

`validate_evidence` sets `field_support_contract: "source_support_v2"`. Each returned charge has `field_support` for `reference_no`, `charge_item`, `amount`, `currency`, `quantity` and `unit_price`; each `total_evidence` entry has amount/currency support. A fact is `{value,score,status,reasons,targets}` with optional `observations`, `ambiguity_kind` and `conflict`. `value` is the current candidate value, never an inferred alternative. Scores are 100 only for supported fields and otherwise 0, not probabilities. Statuses are `supported`, `unsupported`, `ambiguous`, `missing` and `unavailable`.

Only fresh verified references are used. Field-specific references take precedence; otherwise ordinary charge support uses unlabelled references and total support can use all references of that same total. Normalized names may cite preserved `raw_charge_item`. Targets retain actual source metadata and add `value_start`/`value_end`, absolute zero-based, exclusive-end character offsets in original block text. Quote offsets remain original citation offsets. Duplicate aliases with identical content hash, anchor and token span do not multiply targets or support. Different Word/Excel cells with the same text retain their different anchors and remain distinct physical facts. Explicit contradictory references cannot be erased by another reference that happens to match.

The single source-token parser supports `1,234.56`, `1.234,56`, space/NBSP/narrow-space grouping, apostrophe grouping, valid Indian grouping, fullwidth decimal digits/punctuation, Arabic decimal digits and explicit Arabic decimal/group separators, accounting parentheses and Unicode minus. It preserves raw text and offsets. It accepts arbitrary decimal precision rather than assuming every currency has two decimals. Malformed grouping, invoice suffixes and OCR-confused letter/digit runs are not repaired or partially parsed. JSON/trailing sentence punctuation is distinguished from a separator between digits.

Single comma/dot followed by three digits can represent two values (`1,234` → `1.234` or `1234`); both candidates are retained. The model's proposed amount cannot choose between them. Explicit Arabic decimal/grouping characters retain their distinct semantics. Grouping with a leading zero is not accepted as a second reading of an ordinary fractional value such as `0.125`. Numeric observations contain raw token, candidate decimal strings and actual source offsets. No country/language/locale guess or arithmetic-only guess resolves ambiguity.

Currency support accepts complete ISO-code tokens and qualified forms: US$, CA$, AU$/A$, NZ$, HK$, SG$/S$, CN¥, JP¥, R$ and €. It also accepts unique official full names supplied by the installed ISO dataset, such as Euro, US Dollar and Canadian Dollar. A bounded plural rule adds `s` to names ending in dollar/euro/rupee/pound/franc/dinar/dirham/peso/rial/riyal. Local aliases are explicitly limited to 人民币、欧元、日元、美元、加元、澳元、港元、英镑、Chinese Yuan、Japanese Yen. Overlapping spellings of the same currency, such as official Yen inside Japanese Yen, count once at the longest actual span. This is not coverage of every language; unknown names need caller review.

Bare $, ¥/￥, kr, Rs and C$ remain ambiguous; Dollar/Pound/Rupees alone do not establish a country-specific currency. In particular C$ does not establish CAD globally. Codes inside alphanumeric identifiers do not count. Qualified symbols may attach directly to digits, as in US$50. A citation containing multiple different currencies needs a more precise field citation. Code recognition never uses the model's proposed currency to reinterpret source words. Full-uppercase ISO codes remain supported. Known English word/name collisions ALL/TRY/TOP/PEN/MAD/MOP/GEL/CUP/BOB/COP/CAD/RUB/ERN/BAM/SOS in lowercase or title case require an original `currency`/`ccy`/`币种` label immediately before the token (optional colon/equal sign). Bare `All` remains ordinary text even when the model proposes ALL. Non-word codes such as lowercase usd/eur retain case-insensitive support. This bounded rule is not a multilingual word classifier: other local word/code collisions and all-uppercase prose require precise source citations and caller review. A separately cited header may supply explicit currency evidence; another total's evidence is never borrowed.

For a provided amount, currency or charge name, only `supported` passes the evidence Hook. `FIELD_VALUE_UNSUPPORTED` blocks contradicted/unsupported values and values with no applicable current reference (`unavailable`); citing only a quantity cannot bypass amount/currency attribution. `FIELD_VALUE_AMBIGUOUS` blocks numeric-format, currency and location ambiguity. A repeated equal value without a unique field/line location cannot be approved merely because a UI confidence warning exists. `link_evidence` remains pure citation read-back and can succeed while `validate_evidence` correctly rejects the interpretation. Missing values themselves stay `missing` for existing schema/financial gates; no identifier, quantity or unit-price template requirement is added. The financial Skill remains the only arithmetic/rounding implementation.

Preview cell matching uses this same parser. International values with one reading can locate a real cell; ambiguous source amounts stay at row/block granularity. No second confidence or preview-specific number parser is introduced. Source-support protocol is portable JSON and does not import host modules.

Regression for this package includes synthetic international, ambiguity, conflict, preview, identical-cell anchors and standalone-CLI cases plus the seven prior evidence cases. The host's final report records the current count and timing. This demonstrates covered rules, not independent real-world extraction accuracy or online model/OCR performance. Historical regression statements below refer to earlier releases.

Evidence errors are EVIDENCE_MISSING, EVIDENCE_UNREADABLE and EVIDENCE_AMBIGUOUS. `verified=True` means a quote was found uniquely in that source block. It does not establish that the amount, party relationship or proposed UPDATE is semantically correct. Those still require financial rules and applicable human review.

Version 1.1.1 treats an explicit `quote_start: null` like an omitted offset when the original quote occurs exactly once; verified start/end offsets are computed from that unique source occurrence. Repeated identical quotes still require an explicit valid integer offset. No uniqueness or financial attribution rule is relaxed.

## Declared total evidence

`validate_evidence` validates explicit `totals[].evidence` through the same read-back implementation and returns each copied total with its original `total_index` and fresh verified references in `total_evidence`. With no references, the entry has `evidence: []`; absence alone creates no evidence error and loses only the optional total-support score in billing-confidence.

If references are supplied, their amount and currency must support the declared values. Field-specific references take precedence for the corresponding field; when that field has no explicit reference, version 1.1.2 checks all verified references belonging to this same total entry. A quote `Total USD 70` labelled only `amount` can support the currency actually present in that quote; another total's references are never borrowed. An explicit currency reference saying EUR still overrides the amount-labelled USD quote and fails a USD declaration. Decimal token matching keeps 50 distinct from 150. An explicit reference that does not support either value adds `TOTAL_VALUE_UNSUPPORTED` with `severity: error`, `total_index` and `field: totals.amount` or `totals.currency`; normal read-back failures remain errors as well. This is a hard validation failure even when the declared total equals the sum of extracted rows. A high confidence score cannot offset it.

Source read-back and support existence are distinct from the confidence package's stricter unique-occurrence scoring. Repeated supported totals can still lack a unique scoring location. Computed sums are consistency checks, not independently cited original totals.

## Preview and rendering identity

`build_preview(payload)` projects saved source blocks and a read-only display target. Office sources retain original paragraph/table/row/cell anchors; it does not manufacture a fixed physical page for DOCX. Cell location requires one matching saved non-proxy cell; repeated values remain at row/block granularity. Image boxes are exposed only when the saved coordinate format is explicit and valid.

document-intake may supply `metadata.office_preview` with a derived PDF SHA-256, page count and converter version. The preview envelope exposes `render.version` equal to that hash. `render_page`/`render_pages` are supplied only when the block's saved preview mapping references the same PDF hash and valid page numbers. Mapping is based on unique normalized-text matching; the logical source anchor remains authoritative. Repeated or unmatched text keeps its content anchor without invented page or bbox. A changed render or font environment requires a new mapping; rendering is not fresh OCR or new financial evidence.

The host pins this package per task. Existing capability snapshots are not silently upgraded to 1.1.0 when source files change; unavailable historical functionality is reported explicitly.

## Standalone CLI

`python scripts/skill.py --input input.json --output output.json` invokes `link_evidence`; `--operation validate_evidence` selects the existing validation interface. Omit paths or use `-` for stdin/stdout. JSON files are UTF-8, with an optional input BOM; the root input must be an object. Output retains the function's validation envelope and Decimal numbers. Exit 0 requires `valid=true`; rejected evidence, malformed/unreadable input and unwritable output return exit 1. Output failures use stderr; successful file output leaves stdout empty.

Docs MCP `/oss/python/deepagents/skills` and API `SkillsMiddleware`/`FilesystemMiddleware` were rechecked with deepagents 0.7.29: native middleware handles discovery and tool execution, not application JSON file flags. This self-contained `argparse` adapter calls the existing package function once; it adds no agent runner or script execution engine. Shell invocation remains the responsibility of an official sandbox backend or the caller.
